# AI 面试陪练：接口与数据协议

## 1. 目标

本文件把当前演示流程拆成可接入真实模型的 4 个服务节点。前端不直接调用模型，也不保存 API Key；所有模型请求都应通过服务端完成。

## 2. 建议接口

### `POST /api/interview/analyze`

输入简历文本与 JD，返回岗位能力、简历证据、匹配关系和风险项。

输出遵循 `schemas/01-analysis.schema.json`。

### `POST /api/interview/questions`

输入已确认的分析结果，生成固定 5 道题。

输出遵循 `schemas/02-question-set.schema.json`。

### `POST /api/interview/diagnose`

输入当前问题、历史回答、本轮回答和追问次数，返回证据诊断、是否追问及单题反馈。

输出遵循 `schemas/03-answer-diagnosis.schema.json`。

### `POST /api/interview/report`

输入已确认的分析、5 道题及全部回答，生成快速总结与深度报告。

输出遵循 `schemas/04-report.schema.json`。

## 3. 状态机

```text
SETUP
  → ANALYZED
  → QUESTIONS_READY
  → ANSWERING
  → FOLLOW_UP（可选，每题最多2次）
  → QUESTION_COMPLETE
  → REPORT_READY
```

禁止状态跳转：

- 未确认解析结果时直接生成问题；
- 未提交回答时生成单题评分；
- 单题超过 2 次追问；
- 5 道题未完成时生成正式综合报告。

## 4. 服务端校验

每次模型返回后必须：

1. 使用对应 JSON Schema 校验；
2. 格式失败时仅重试一次；
3. 检查引用的 `evidence_id` 是否真实存在；
4. 检查评分是否在 1～5 范围；
5. 检查报告是否新增简历和回答中不存在的事实；
6. 删除不必要的姓名、电话、邮箱等信息后再写日志。

## 5. 隐私规则

- API Key 只能放在服务端环境变量中；
- 默认不记录原始简历全文；
- 日志使用会话 ID，不使用候选人姓名；
- 测试数据应脱敏；
- 用户应能在提交前查看并修正解析结果；
- 用户未主动保存时，会话结束后不应长期保留原始材料。

## 6. MVP 错误码

| 错误码 | 含义 | 前端处理 |
|---|---|---|
| `RESUME_PARSE_FAILED` | 简历无法提取文本 | 提示用户粘贴文本 |
| `JD_TOO_SHORT` | JD 信息不足 | 提示补充职责与要求 |
| `MODEL_FORMAT_ERROR` | 模型输出未通过 Schema | 自动重试一次 |
| `EVIDENCE_REFERENCE_ERROR` | 引用了不存在的证据 | 删除错误引用并重试 |
| `RATE_LIMITED` | 模型请求过于频繁 | 保留回答并稍后重试 |
| `REPORT_INCOMPLETE` | 面试尚未完成 | 返回未完成题目 |
